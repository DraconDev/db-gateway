## Measured RPO and RTO

- **RPO lag (actual): 1822 s (~30 min)** — age of the newest verified
  set (`20261015T231717Z`) when verified at 1792108059. The timer runs
  hourly, so the steady-state worst case is ~60 min plus run duration;
  this drill caught the cycle mid-way.
- **RTO (actual): 38 s (<1 min)** — wall clock from starting the set
  pull to a verified independent restore (pull + local verify + import
  + integrity/FK/row checks). Scales with database size; `verify_probe`
  is 24 KiB, so read this as the procedure floor, not a large-DB
  promise.

## Limits

Single-database, 5-row, 24 KiB restore: it proves the procedure and the
measurements, not large-DB timing. Tombstone and corrupt-input negative
cases are covered by the committed suite (`backup_pipeline`,
`recovery_drill`) and were not re-run against live data.
