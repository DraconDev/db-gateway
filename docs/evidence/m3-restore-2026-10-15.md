# M3 restore proof — micro2 set to disposable target (2026-10-15)

Restore path **B** (fresh registry, validated import) per
`docs/recovery-contract.md` §3. The live source was never written by
this drill; every live contact was a read (set listing, backup verify,
row-count queries). The drill is a committed script —
`scripts/m3-restore-drill.sh` — and its verbatim transcript is
`docs/evidence/m3-restore-drill-2026-10-15.log`: every JSON, hash, timestamp,
and check below is quoted from that log, not summarized from memory.
Pulled live bytes stayed in a mktemp workdir removed on exit; the log
retains the full 64-hex hashes.

## Restore (disposable local target)

1. Fresh `dg init` in an empty dir (empty-registry target), serve on
   loopback.
2. `dg import verify_probe --from <pulled>/verify_probe.sqlite` →
   `{"imported":"verify_probe"}` (exit 0) — the validated-import path,
   never a file copy into a running data dir.
3. `dg export` of the restored copy reports sha
   `66222dd0c7a305e84ac12e6da13df8af5ea1c21f7ab841a29b892cd431bb251d`
   (`[EXPORT_JSON]`), byte-identical to the manifest.

## Measured RPO and RTO

- **RPO lag (actual): 2294 s (~38 min)** — `[RPO_LAG_SECS]`, recomputable
  as `[VERIFY_EPOCH] 1792108531 − [SET_STARTED] 1792106237`. The timer
  runs hourly, so the steady-state worst case is ~60 min plus run
duration; this drill caught the cycle past mid-way. (An earlier manual
pass measured 1822 s against the same set.)
- **RTO (actual): 5 s** — `[RTO_SECS]`, wall clock `[RTO_START]
  1792108528` → `[RTO_END] 1792108533` covering pull + local verify +
import + integrity/FK/row/scoped-access checks. Scales with database
size; `verify_probe` is 24 KiB, so read this as the procedure floor,
not a large-DB promise. (The earlier manual pass took 38 s including
SSH-tunnel setup.)

## Limits

Single-database, 5-row, 24 KiB restore: it proves the procedure and the
measurements, not large-DB timing. Tombstone and corrupt-input negative
cases are covered by the committed suite (`backup_pipeline`,
`recovery_drill`) and were not re-run against live data.
