$ turso db create --help
Create a database.

Usage:
  turso db create [flags] [database-name]

Flags:
      --csv-separator string    CSV separator character. Must be a single character. (default ",")
      --csv-table-name string   name of the table in the csv file
      --enable-extensions       Enables experimental support for SQLite extensions.
      --from-csv string         create the database from a csv file
      --from-db string          Select another database to copy data from. To use data from a past version of the selected database, see the 'timestamp' flag.
      --from-dump string        create the database from a local SQLite dump
      --from-dump-url string    create the database from a remote SQLite dump
      --from-file string        create the database from a local SQLite3-compatible file
      --group string            create the database in the specified group
  -h, --help                    help for create
      --location string         Location ID. If no ID is specified, closest location to you is used by default.
      --schema string           Schema to use for the database
      --size-limit string       The maximum size of the database in bytes. Values with units are accepted, e.g. 1mb, 256mb, 1gb
      --timestamp string        Set a point in time in the past to copy data from the selected database. Must be used with the 'from-db' flag. Must be in RFC3339 format like '2023-09-29T10:16:13-03:00'
      --type string             Type of the database to create. Possible values: regular, schema. (default "regular")
  -w, --wait                    Wait for the database to be ready to receive requests.

Global Flags:
  -c, --config-path string   Path to the directory with config file

$ turso db shell --help
Start a SQL shell.
When database-name is provided, the shell will connect the closest replica of the specified database.
When the --instance flag is provided with a specific instance name, the shell will connect to that instance directly.

Usage:
  turso db shell <database-name | replica-url> [sql] [flags]

Examples:
  turso db shell http://127.0.0.1:8080
  turso db shell name-of-my-amazing-db
  turso db shell name-of-my-amazing-db --location yyz
  turso db shell name-of-my-amazing-db --instance a-specific-instance
  turso db shell name-of-my-amazing-db "select * from users;"

Flags:
      --attach strings    list of database names with attach claim to be added to the token
  -h, --help              help for shell
      --instance string   Connect to the database at the specified instance.
      --location string   Connect to the database at the specified location.
      --proxy string      Proxy to use for the connection.

Global Flags:
  -c, --config-path string   Path to the directory with config file

$ turso db export --help
Export a database snapshot and WAL from Turso to SQLite files.

This command exports a snapshot of the current generation of a Turso database
to a local SQLite file, along with any WAL (Write-Ahead Log) frames. The WAL
file will be saved as <database>.db-wal alongside the main database file.

Usage:
  turso db export <database> [flags]

Flags:
  -h, --help                 help for export
      --output-file string   Specify the output file name (default: <database>.db)
      --overwrite            Overwrite output file if it exists.
      --with-metadata        Include metadata in the export.

$ turso dev --help
starts a local development server for Turso.

If you're using a libSQL client SDK that supports SQLite database files on the local filesystem, then you might not need this server at all.
Instead, you can use a file: URL with the path to the file you want the SDK to read and write.

Usage:
  turso dev [flags]

Flags:
  -a, --auth-jwt-key-file string   Path to a file with a JWT decoding key used to authenticate clients in the Hrana and HTTP APIs. The key is either a PKCS#8-encoded Ed25519 public key in PEM, or just plain bytes of the Ed25519 public key in URL-safe base64.
  -f, --db-file string             A file name to persist the data of this dev session
  -h, --help                       help for dev
  -p, --port int                   the port to which bind the server (default 8080)
  -v, --version                    sqld version

Global Flags:
  -c, --config-path string   Path to the directory with config file
