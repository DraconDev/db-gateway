## 6. Lessons / follow-ups

- A drill key was printed into a session log once (my error); it was revoked
  in teardown and is dead. Keys must go to files via `jq -r`, never stdout.
- Restores are point-in-time: the stored set still contains the since-revoked
  drill key. Production restores need a post-restore key audit
  (revoke-unknown-keys) — add to the restore runbook before real data.
- Same-disk snapshots cover logical loss only, not disk loss. The off-host
  pull was manual this time.
- Proposed, not installed: hourly `micro2-backup.sh` cron (as dg) + the R11
  journald cap + `MemoryMax` after D1 numbers. Each needs its own approval.
- OVH/Litestream: deferred per owner — `docs/ovh-sandbox-runbook.md` stands
  ready for when a bucket exists.
