# DB Gateway

**`dg`** is a planned single-owner SQLite service: one Rust gateway, many independent databases, an HTTP API and CLI, and off-host backups.

**Status: local foundation only.** No SQL execution, credentials, database management, backup integration, or application client exists yet. Do not deploy this as a database service.

## Local development

Install a current stable Rust toolchain with `rustfmt` and `clippy`. No production credentials, server access, or bucket are required.

```sh
cargo build --locked
cargo run --locked -- --help
cargo run --locked -- --version
cargo run --locked -- serve --listen 127.0.0.1:7432
```

In another terminal:

```sh
curl --fail-with-body http://127.0.0.1:7432/health/live
# {"status":"ok"}
```

Only loopback addresses are accepted in this milestone. The default is `127.0.0.1:7432`; an occupied port fails startup. Ctrl-C or SIGTERM stops the server on Unix. Startup/server errors and logs are JSON on stderr; CLI usage errors are generated by Clap and use its human-readable format. No credentials are read or written.

`GET /health/live` indicates only that the HTTP process can respond. It makes no assertion about database readiness, durability, or backup health. Unknown routes return 404.

## Checks

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
```

`Cargo.lock` is tracked to fix dependency resolution. CI runs these checks on stable Rust.
